# 雀魂青云之志S4自动刷分脚本

1920×1080 分辨率下自动识别牌面、匹配目标牌、点击自摸/跳过的 Python 脚本。

本脚本适用于以下及类似卡片阵容（冬实效果的牌触发自摸，其余触发跳过）：

## 原理

1. **截图** — 每轮循环合并截取牌面 + 分数区域（175×223），mss 直接返回 ndarray 后切片取出两个 ROI
2. **ORB 特征匹配** — 对截图提取 ORB 特征点；与预设的目标/干扰模板进行 BFMatcher 交叉匹配，取好匹配数（Hamming < 50）最多的模板
3. **决策** — 最佳模板的匹配数 ≥ 阈值(20) 且是目标牌 → 点自摸；否则点跳过
4. **分数检测** — Tesseract OCR（灰度图直出，PSM 7）读取分数（格式 `abc/184`），画面未完全更新时每 0.2s 重试直到读取到稳定分数；低于 `NUM_ALARM(105)` 时报警
5. **连点** — 自摸后连点屏幕中心跳过结算页面
6. **卡住检测** — 每轮比较当前截图与上一轮截图，连续 5 次相同则判定画面卡住，报警弹窗

## 环境要求

- Python ≥3.14
- Windows（使用了 `winsound`、`ctypes`、`keyboard` 等 Windows 特有库）
- Tesseract-OCR 5.4.0+
- 屏幕分辨率 **1920×1080**，游戏窗口全屏

### 安装依赖

```bash
uv sync
```

手动安装 Tesseract-OCR：

## 使用

```bash
uv run python main.py           # 静默运行（无信息窗口）
uv run python main.py --debug   # 带 Tkinter 调试窗口
```

运行后弹出确认窗口，切换到游戏窗口后点击确认即可开始。

## 模板配置

### 目录结构

```
consts.py              # 全部常量（坐标、阈值、路径、DEBUG 标志）
capture.py             # 截屏（mss，合并 175×223 区域）
tile_matcher.py        # 牌型匹配（ORB 特征 + BFMatcher，模板加载）
score_reader.py        # 分数检测（Tesseract OCR，含 debug 截图）
clicker.py             # 点击动作（自摸/跳过）
ui.py                  # 用户交互（报警、暂停弹窗、debug 窗口）
main.py                # 入口，主循环
pics/
├── targets/          # 目标牌模板（触发自摸）
│   ├── 1m.png
│   ├── 1p.png
│   ├── 9m.png
│   ├── 9p.png
│   ├── 9s.png
│   └── dong.png
└── distractors/      # 干扰牌模板（触发跳过）
    ├── 7p.png
    └── 7s.png
tools/
├── mouse_pos.py       # 坐标捕获工具
└── threshold_test.py  # 阈值检测测试工具
```

模板为游戏内手动截图（原始像素尺寸，无缩放），ORB 在加载时自动提取特征点。

### 目标牌

`1m`（一萬）、`9m`（九萬）、`9s`（九條）、`1p`（一筒）、`9p`（九筒）、`dong`（東）

## 坐标配置

所有坐标基于 **1920×1080** 全屏：

| 常量 | 坐标 | 说明 |
|------|------|------|
| `TILE_REGION` | (450, 885, 90, 140) | 牌面截图区域 (left, top, width, height) |
| `NUM_REGION` | (365, 805, 125, 30) | 分数数字区域 |
| `CENTER` | (960, 540) | 屏幕中心（连点/鼠标复位） |
| `TSUMO_BTN` | (1200, 820) | 自摸按钮 |
| `SKIP_BTN` | (500, 950) | 跳过按钮 |

## 阈值说明

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `THRESHOLD_DEFAULT` | 20 | 全局匹配数阈值 |
| `NUM_ALARM` | 105 | 分数低于该值时报警暂停 |
| `RETRY_LIMIT` | 5 | OCR 分数异常重试上限 |
| `LOOP_SLEEP` | 1.2 | 每轮循环间隔（秒） |
| `SLEEP_INTERVAL` | 0.2 | 检测/重试刷新间隔（秒） |

阈值是 **好匹配数**（BFMatcher 交叉匹配中 Hamming 距离 < 50 的匹配对数）。模板特征总数越多，理论上可达的匹配数越高。

## 详细流程

```
┌─────────────┐
│ 加载模板     │  读取 targets/ 和 distractors/ 下的图片，
│ 提取特征点   │  用 ORB 提取特征描述子
└──────┬──────┘
       ↓
┌─────────────┐
│ 弹窗确认     │  点击确认后开始运行
└──────┬──────┘
       ↓
┌─────────────┐  ─── 循环开始 ───
│ 鼠标移至中心 │  (960,540)
├─────────────┤
│ 合并截屏     │  175×223（mss），切片取牌面 + 分数 ROI
├─────────────┤
│ 卡住检测     │  与上一轮截图比较，连续5次
│             │  相同 → 报警弹窗
├─────────────┤
│ ORB 特征匹配 │  有匹配数 > 50 时提前退出
│             │  对所有模板计算好匹配数，取最高者
├─────────────┤
│ OCR 读取分数 │  格式 abc/184，灰度图直出
│             │  分数大幅下降时等待稳定（连续两次相同）
│             │  < NUM_ALARM → 报警
├─────────────┤
│ 决策         │  最佳模板是目标 且 匹配数≥阈值(20)
│             │  → 自摸        → 跳过
└──────┬──────┘  └──────┬──────┘
       │                │
       │ 1. 移到自摸按钮 │ 1. 移到跳过按钮
       │ 2. 点击        │ 2. 点击
       │ 3. 连点屏幕中心 │ 3. 鼠标复位中心
       └────────────────┘
       ↓
    休眠 1.2 秒 → 循环继续
```

## 分数报警

当 OCR 读取到分数且当前值 `cur < NUM_ALARM(105)` 时：

1. 响五声提示音（660Hz × 5）后接系统警告音
2. 弹出 Windows 消息框（确定继续，取消退出）

OCR 灰度图直出 Tesseract（PSM 7），无二值化/放大预处理。

## 画面卡住检测

程序每轮比较牌面截图像素，连续 5 次完全一致时触发卡住报警：

1. 响五声提示音（660Hz × 5，各 200ms）后接系统警告音
2. 弹出 Windows 消息框（确定清零计数继续，取消退出）

卡住检测基于像素级比较（`np.array_equal`），不依赖 ORB 识别结果。

## 异常处理

主循环包在 `try/except BaseException` 中，任何异常会打印堆栈并调用 `os._exit(1)` 安全退出。`Ctrl+C` 和 `SystemExit` 不受影响。

## 调试窗口

`--debug` 参数开启 Tkinter 信息窗（右下角 550,770，固定 260×150，Consolas 16 bold），实时显示：
- 当前 OCR 分数
- 当前动作（自摸/跳过）及牌面名/匹配度

## 开发备注

- 不要缩放模板图像，保持原始像素尺寸（手动截图时的尺寸）
- ORB nfeatures=200，好匹配距离上限 50，good>50 时提前退出循环
- 检测器与 BFMatcher 在模块级缓存复用（`tile_matcher._ORB` / `tile_matcher._BF`）
- 使用 `cv2.NORM_HAMMING` + `crossCheck=True` 的 BFMatcher
- 干扰模板（distractors/）中任意图片被判定为最佳时会强制跳过
- 截屏用 `mss` 替代 `pyautogui.screenshot`：只捕获指定区域（不截全屏），直接返回 ndarray，延迟降至 ~5-15ms
- 牌面与分数区域合并为一次 `mss.grab`（`left=365, top=805, width=175, height=223`），numpy 视图切片取出两个 ROI，API 调用减半
- 无匹配时等待 0.2s 重试一次（重截屏+重新匹配），仍无匹配才跳过
